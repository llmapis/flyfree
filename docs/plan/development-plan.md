# Flyfree 开发计划

## 项目概述

**项目名称**: Flyfree
**开发语言**: TypeScript
**分发方式**: npm 包
**目标**: 为用户提供便捷的 LLM Provider 配置管理和切换工具

## 一、技术选型（已确认）

### 1.1 命令行框架：Commander.js ✅

- **特点**:
  - 最流行的 Node.js 命令行框架之一
  - API 简洁直观
  - 支持子命令、选项解析
  - 社区成熟，文档完善
- **GitHub**: https://github.com/tj/commander.js
- **选择理由**: 成熟稳定，社区资源丰富，适合 Flyfree 的需求复杂度

### 1.2 命令行交互库：@inquirer/prompts ✅

- **特点**:
  - Inquirer.js 的新版本模块化包
  - 现代化 API 设计
  - 支持多种提示类型（列表、确认、输入等）
  - 按需导入，体积更小
- **GitHub**: https://github.com/SBoudrias/Inquirer.js
- **选择理由**: 功能完整，模块化设计，满足交互式选择需求

### 1.3 其他依赖库

#### HTTP 请求库

- **推荐**: `axios`
- **用途**: 从订阅 URL 获取配置信息

#### 文件系统操作

- **推荐**: `fs-extra`
- **用途**: 增强的文件系统操作（创建目录、读写 JSON 等）

#### 路径处理

- **推荐**: Node.js 内置 `path` 模块
- **用途**: 处理 `~/.ff/` 等路径

#### Hash 计算

- **推荐**: Node.js 内置 `crypto` 模块
- **用途**: 计算配置内容的 hash 值

#### 终端美化

- **推荐**: `chalk`（文字颜色）、`ora`（加载动画）
- **用途**: 提升用户体验

#### JSON Schema 验证

- **推荐**: `ajv`
- **用途**: 验证订阅 URL 返回的配置格式是否符合规范

## 四、技术难点与解决方案

### 4.1 跨平台路径处理

**问题**: `~/.ff/` 在不同操作系统的处理
**解决方案**: 使用 `os.homedir()` 获取用户目录，`path.join()` 拼接路径

### 4.2 配置文件安全 ✅

**问题**: 写入配置可能导致原配置丢失
**解决方案**:

- 每次修改前自动备份到 `~/.ff/backups/{agent}/{timestamp}.json`
- 完全覆盖原配置文件（简单可靠）
- `--auto` 参数跳过确认，否则需用户确认后再应用
- 使用原子写入（写临时文件再重命名）
- 配置回滚功能可作为后续扩展

### 4.3 并发订阅处理

**问题**: 用户同时执行多个订阅命令可能冲突
**解决方案**: 使用文件锁机制（如 `proper-lockfile`）

### 4.4 网络请求失败处理

**问题**: 订阅 URL 可能无法访问
**解决方案**:

- 设置合理的超时时间
- 实现重试机制
- 保存失败信息到 `latest_response_message`
- 提供详细的错误提示

### 4.5 配置格式验证

**问题**: 订阅 URL 返回的数据格式不符合规范
**解决方案**:

- 使用 JSON Schema 严格验证
- 提供清晰的验证错误信息
- 拒绝不符合规范的配置

## 五、数据结构补充说明

### 5.1 Agent 配置路径映射 ✅

在代码中维护一个可扩展的配置映射表:

```typescript
const AGENT_CONFIG_PATHS: Record<string, string> = {
  "claude-code": "~/.claude/settings.json",
  // 其他 agent 路径可后续添加
  // 'codex': '~/.codex/config.json',
  // 'qwen-cli': '~/.qwen/config.json',
};
```

**设计原则**:

- 采用可配置的映射表结构，便于扩展
- 未知路径的 agent 预留接口，用户可后续手动添加
- 在配置文件中也可以定义 agent 路径映射（高级功能）

### 5.2 订阅协议规范

建议创建一个详细的协议文档，定义:

- 订阅 URL 的 HTTP 响应格式
- 必需字段和可选字段
- 各字段的数据类型和验证规则
- 错误响应格式

这将便于第三方 provider 实现兼容接口。
